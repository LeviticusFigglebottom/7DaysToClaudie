# Playable builds

Hollowmere's models, textures and sounds are generated by this repository's code (`make assets`)
and are not committed. The toolchain that generates them runs on Linux x86_64. So:

* **To play**, use a packaged build: it includes everything.
* **To develop**, clone the repository and run `make setup assets` on Linux. Without that step the
  game still runs, but every model is a simple stand-in shape (no textures, no grass), and the main
  menu says so (ADR-0036).

## Getting a packaged build
The **Build** workflow (`.github/workflows/build.yml`) runs on every push to the integration
branch and on demand (Actions → Build → Run workflow). Each run uploads:

| Artifact | Contents |
|---|---|
| `hollowmere-windows` | `Hollowmere.exe`, `Hollowmere.console.exe` (same game, with a log console), `Hollowmere.pck`, README, notices |
| `hollowmere-linux` | `Hollowmere.x86_64`, `Hollowmere.pck`, README, notices |

Unzip and run. Keep the `.pck` next to the program. A GPU with Vulkan 1.2 or Direct3D 12 is
needed (older drivers make Godot fall back to OpenGL, where fog, weather and lighting are wrong).

Saves, settings and logs: `%APPDATA%\hollowmere\` on Windows, `~/.local/share/hollowmere/` on
Linux. `logs/godot.log` is the log of the last run: send it with any crash report.

## Building one yourself (Linux)
```bash
make setup         # pinned Godot, Blender, Python (once)
make assets        # every generated asset (first run: a few hours on 4 cores; incremental after)
make export        # build/export/hollowmere-{windows,linux}-<version>-<rev>.zip
```
`make export` installs the pinned export templates (`tools/versions.env`, SHA-512 checked) into
`.tools/xdg` on first use. `EXPORT_TARGETS=linux` exports one platform; `EXPORT_STANDIN=1`
packages a build without generated assets (for testing the stand-ins only).

Check a pack: `python3 tools/export/pck_list.py build/export/windows/Hollowmere.pck` lists its
files. Smoke an exported pack (export templates ignore `-s`, so use the editor binary):
```bash
cd /tmp && /path/to/repo/.tools/godot/godot --headless --main-pack /path/to/Hollowmere.pck \
  -s /path/to/repo/game/src/tools/cli/slice_smoke.gd
```

## Stand-in mode
What a fresh clone runs before `make assets`: `ModelLibrary.make_placeholder` shapes and the
other procedural fallbacks. CI keeps it working (the **Stand-ins** workflow: import, check, tests,
`make smoke` and `make tour`, no Blender). `make tour` sprints the player into one of everything
and hits and uses it; run it after touching anything a player can bump into.
